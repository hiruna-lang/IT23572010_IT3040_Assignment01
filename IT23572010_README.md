# IT23572010 - IT3040 Assignment 1

## Automated Testing for Chat-Style Singlish to Sinhala Transliteration

---

## 1. Project Overview

This project was developed for IT3040 Assignment 1 - Option 1.

The purpose of this project is to test the PixelsSuite Chat Translator web application using automated UI testing. The system was tested using chat-style Singlish inputs to check whether the application produces the expected Sinhala transliteration output.

Tested website:

https://www.pixelssuite.com/chat-translator

Repository link:

Add your GitHub repository link here

---

## 2. Project Objective

The main objective of this assignment is to identify cases where the Singlish to Sinhala transliteration system does not generate the expected Sinhala output.

This project focuses on negative testing. The test cases include informal Singlish messages, mixed English words, spelling variations, platform names, online identifiers, numbers, dates, time values, and emojis.

## 9. How to Run the Automation

Before running the automation script, make sure the Excel file is closed.

First, open the browser with remote debugging enabled:

    taskkill /F /IM brave.exe

    start "" "C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe" --remote-debugging-port=9222 "https://www.pixelssuite.com/chat-translator"

Wait until the PixelsSuite Chat Translator page is fully loaded.

Then run the automation script:

    python IT23572010_test_automation.py --excel "C:\IT23572010\IT23572010_Test_Cases.xlsx" --input-col "Input" --expected-col "Expected output" --actual-col "Actual output" --status-col "Status" --wait-ms 20000 --timeout-ms 150000 --type-delay-ms 250 --save-every 1

## 10. Output Generation

After the script is executed, the Excel file is updated automatically.

The following columns are updated:

- Actual output
- Status

The status is generated by comparing the expected Sinhala output with the actual Sinhala output returned by the web application.

---

## 11. Validation Method

The validation method used in this project is strict comparison.

A test case is marked as FAIL when the actual output is different from the expected output. Differences may include:

- Sinhala spelling differences
- Incorrect word conversion
- Missing or changed punctuation
- Spacing differences
- Formatting differences
- Incorrect handling of English words
- Incorrect handling of URLs
- Incorrect handling of email addresses
- Incorrect handling of numbers, dates, time values, or emojis

Since this project focuses on negative testing, the test cases are designed to identify incorrect or inconsistent transliteration results.
